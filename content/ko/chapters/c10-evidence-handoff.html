검토 가능한 기록으로 결론·한계·후속 증거를 전달합니다.

재사용 가능한 WAT 결론 작성

엔지니어링 인계 문서는 다른 엔지니어가 비교를 재현하고 한계를 이해할 수 있어야 합니다. 질문과 의사결정, 구조와 모집단, 원시·추출 파라미터 정의, 시험·추출·맵 버전, 표본 계층과 제외, 추정치와 불확도, 측정 유효성 점검, 분석법, 강한 지지·반대 증거, 해결되지 않은 가정을 적으십시오.

간결한 결론 예시: “[정의된 모집단과 기간]에서 [명명된 파라미터]가 [프로토콜]로 측정되어 [추정치와 표본 계층]만큼 변했다. [불확도]를 고려할 때 기준선과의 변화는 [검출됨 / 아직 분해되지 않음]이다. 증거는 [제한된 가설]과 일치하지만 [대안]은 남아 있다. [후속 측정]으로 [예측]을 구분할 수 있다. 이 문장은 [인과관계·제품 영향·처분]을 입증하지 않는다.”

공유 전 재현성 점검

  • 저장소 테스트를 실행하고 사이트를 빌드해 두 언어가 같은 장 순서인지 확인합니다.
  • 보고할 모든 시뮬레이터 URL과 앵커를 배포된 버전에서 검증합니다.
  • 접근 제어를 바꾸지 않고 원시 데이터 ID와 분석 스크립트를 연결합니다.
  • 라이선스 고지, 인용 정보, 데이터 출처를 보존합니다.
  • 검토 범위와 남은 기술 한계를 기록합니다.

WATBook 테스트는 결정론적 식, 입력 경계, 경로 생성, 브라우저 흐름을 확인합니다. 시험 시스템을 인증하거나 반도체 공정을 검증하거나 실험실 데이터를 대체하지 않습니다. 참고문헌과 용어의 모델 상태 표는 수학적 확인과 외부 출처 확인을 구분합니다.

권장 학습 순서

1–3장에서 의사결정과 측정 계약을 정합니다. 4–6장은 추출 및 계층 데이터 검토에 활용합니다. 7–9장은 구조화된 조사에, 10장은 추적 가능한 인계에 활용합니다. 여섯 개 실험은 작은 학습 도구이며 자동 제어·출하 시스템이 아닙니다.

소자 원리부터 학습하려면 DeviceBook, 일반 공정 제어와 수율은 YieldBook, 제품별 BCD 사례는 PMICBook으로 이어가십시오. My Library의 제안 로드맵은 고급 모듈 통합과 제조 운영 제어를 별도의 미래 교재로 구분합니다.

최종 검토 질문
  1. 어떤 측정과 모집단이 주장을 뒷받침하는가?
  2. 가능한 아티팩트 중 무엇을 실험으로 확인했는가?
  3. 반복 사이트·웨이퍼·로트는 어떻게 처리했는가?
  4. 어떤 관측이 현재 해석을 바꾸게 되는가?
  5. 제품 의사결정에 활용하기 전에 어떤 한계를 해소해야 하는가?
